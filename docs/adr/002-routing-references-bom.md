# ADR-002: 라우팅 헤더는 품목(Item) 대신 BOM을 직접 참조한다

## 상태
승인됨

## 날짜
2026-03-25

## 맥락

라우팅(공정순서) 도메인을 설계하면서 헤더 엔티티가 무엇을 기준으로 공정 순서를 묶을지 결정해야 했다.
BOM은 `(품목, 버전)` 쌍으로 생산 자재 명세를 정의하며, 라우팅은 동일한 생산 단위에 대한 공정 순서를 정의한다.

## 검토한 선택지

- **선택지 A — 품목(Item) + 버전 참조**: `Routing(itemId, version)` — BOM과 독립적으로 버전 관리
- **선택지 B — BOM 직접 참조**: `Routing(bomId)` — BOM 1개에 라우팅 1개 대응

## 결정

**선택지 B** — `Routing` 헤더가 `bomId`를 FK로 가지며, `bomId`에 UNIQUE 제약을 둔다.

BOM이 이미 `(품목, 버전)`을 캡슐화하고 있으므로, 라우팅이 동일한 키를 중복 관리할 이유가 없다.
생산 실행 시 "이 BOM으로 만들 때 공정은 어떻게 되는가"라는 자연스러운 질의가 가능하다.

## 결과

### 긍정적
- 라우팅에 별도 버전 필드가 없어 모델이 단순해진다
- BOM ID 하나로 자재 명세(BOM)와 공정 순서(Routing)를 모두 조회할 수 있다
- 중복 버전 관리 로직 제거로 서비스 코드가 간결해진다

### 부정적 / 트레이드오프
- 동일 품목에 대해 BOM 버전과 라우팅을 독립적으로 변경할 수 없다
  (공정 순서만 바꾸려면 새 BOM 버전을 먼저 만들어야 함)
- 라우팅 등록 UI에서 BOM 목록을 먼저 로드해야 하므로 UX 단계가 하나 늘어난다
